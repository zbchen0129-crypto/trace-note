当前状态：材料与工具准备完成；真实评审者 0 人，真实提交 0 份，没有独立标注结果或准确率结论。

发给评审者的文件仅为 `artifacts/review/tracenote-blind-review-v1.zip`。不要发送整个源码包、仓库或本目录，这些地方包含开发参考与模型结果。ZIP 采用三文件白名单：INSTRUCTIONS.md、materials.json、response-template.json。它隐藏的是参考解释和模型结果，不隐藏作者与出处，不应称为双盲实验。

## 招募与收集

需要两位能阅读英文材料、愿意独立判断的真实评审者。开发助手不能充当独立评审者。已看过开发解释或模型输出的人须在 priorExposure 中注明；不要把这种提交与未接触答案的评审混合解释。没有自动发送邀请、收集身份或联系任何人。

两人各自在相同包上独立填写，用匿名代号，无需姓名/邮箱。请只按包内材料判断，不查阅外部全文或互相讨论，以免给定材料范围不一致。材料是完整摘录视图，不安排“先只看引述、再看评价”的配对任务，避免前一阶段记忆影响下一阶段的解释。R01/R02 共享达尔文来源，R03 是论文来源，三个任务并非三个独立文档样本。

将收到的原始文件保存到本机项目外的评审资料位置，不放入会公开的仓库、eval/results 或源码包。工具只读输入，默认把结果输出到终端，不自动上传或保存真实回答。讨论前分别检查：

```sh
python3 eval/blind_review.py validate /path/to/reviewer-a.json
python3 eval/blind_review.py validate /path/to/reviewer-b.json
python3 eval/blind_review.py compare /path/to/reviewer-a.json /path/to/reviewer-b.json
```

检查只判断完整性、版本及引文是否来自指定材料，不能判断解释正确。相同匿名 ID 被拒绝，但工具无法验证两份回答是否来自不同真人。每个输入最多 128 KB；逐个读取；没有模型请求。

## 比较与讨论

工具并排保留每题的立场、观点提出者、评价者、证据和备注。先看立场分歧，再看“立场一致但人物或证据不同”的情况。任务数量过小且共享来源，不计算或宣传统计可靠性、提效、显著性或准确率。

独立提交后再讨论，原始文件保持不变。另建讨论记录，写下 caseId、双方原始解释、分歧原因、是否达成共识、仍有争议的地方及是否需要额外原文。不要强迫达成单一答案，也不要用开发参考压过真实分歧。
