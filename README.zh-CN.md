# TraceNote

A local qualitative research workbench with evidence-linked annotations, versioned codebooks, SQLite history, and human-reviewed AI proposals.

**v0.2：本地数据库与真实 AI 核心流程已验证。** 默认材料为虚构教学摘录。测试模型仅存在于测试代码，生产服务不生成假 AI 结果。

## 启动

需要 Python 3.10+，后端仅使用标准库。不要再用静态 `http.server` 启动：

```sh
cd trace-note
python3 server.py
```

访问 http://localhost:8767 。首次启动时，如果数据库为空，页面会迁移该浏览器原有的 TraceNote localStorage 项目；旧浏览器记录保留。数据库已有项目时以数据库为准。

## 配置 AI

在项目根目录的 `.env` 中填写：

```dotenv
OPENAI_API_KEY=你的API密钥
TRACENOTE_MODEL=你账户可用且支持Responses结构化输出的模型名称
```

空白 `.env` 已在本地准备好；仓库只跟踪 `.env.example`。修改后重启 `python3 server.py` 并刷新页面。密钥仅由服务端读取，不发送到前端、不写入数据库、不打印日志。环境变量优先于 `.env`。

点击生成先预览，确认后将当前段落、同一材料相邻段落、最多 4 段手选补充上下文和当前标签规则发送到 OpenAI；请求规则建议还包含最近人工纠正及相关模型建议。虚构摘录集合不提供相邻片段作为上下文。没有凭据或模型名称时按钮禁用，人工操作仍可使用。

接口实现根据 [OpenAI Structured Outputs 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs/) 使用 Responses API 的 `text.format` JSON schema；请求设置 `store: false`。真实账户权限、模型兼容性及效果需配置后验证。

## 工作流

1. 导入 TXT 或粘贴访谈，空行分段，保留原文与稳定段落 ID。
2. 手工标注，或生成 AI 建议。每个标签的连续引文必须精确匹配原文；AI 引文出现多次时拒绝自动定位。
3. 载入建议到表单，修改后确认或拒绝并记录原因。建议不直接进入主题汇总。
4. 保存人工纠正和备注后请求规则修改建议；载入规则编辑器，预览差异，再确认发布。
5. 新版本发布后，旧判断重新复核；模型请求期间发生规则变化，返回建议保留其原版本，不能直接接受。
6. 从汇总跳回原文。JSON 导出包含完整记录；JSON 恢复目前恢复材料、规则、人工判断，**不导入 AI 建议及审核关联**。恢复前项目保留在 SQLite 历史快照中。

## 持久化与并发

`data/tracenote.sqlite3` 保存追加式项目快照及模型任务状态。每次写入检查 revision，冲突返回 409，要求刷新后重试，不覆盖其他页面。多页面冲突时未保存表单需自行复制保留。

模型任务持久化 running/completed/failed；相同 requestId 去重。模型调用最多等待 60 秒，不自动重试付费请求；用户主动再次生成会使用新 requestId。服务重启时未完成任务标记失败。生成失败不增加有效建议。

这是单用户本地原型：服务仅绑定回环地址，校验 Host/Origin，不用于公网部署。每次保存完整项目快照，暂不适合大规模材料。JSON 请求上限 5MB，单次模型输入上限约 4 万字符。

## 代码结构

- `web/domain.js`：人工标注、版本及汇总逻辑。
- `web/app.js`：操作界面、迁移、异步保存、建议审核与恢复。
- `backend/core.py`：SQLite 事务、不可变历史、原文与 UTF-16 引用位置校验。
- `backend/model.py`：服务端 Responses API、结构化输出与引文验证。
- `backend/service.py`：模型任务、规则建议、审核决策。
- `server.py`：本地 HTTP 服务与 API。

为复用当前无依赖运行环境，此轮使用 Python 标准库和原生 JS；TypeScript 迁移尚未实施。

## 多研究问题（本地已实现）

顶部“新增研究问题”填写问题、初始标签名称与定义，创建后切换到独立规则页。一个项目最多 20 个问题，共享材料与段落 ID，各自拥有规则、标注、AI 建议、进度和汇总。新问题从一个自定义标签开始，可修改其定义与研究范围；在“标签与版本”可新增、改名、移除标签。

已有记录继续属于原来的公共交通问题，不复制或改写历史。更新问题 B 的规则只要求复核 B 的判断，A 保持原状。版本编号仍是项目全局编号，因此一个问题的版本号可能不连续。问题文字创建后不直接修改；研究含义变化应建立新问题。

浏览器验收使用隔离数据库：原问题确认 P001，新建照护问题后 P001 仍为待标注；保存“我得接孩子”后只进入照护问题汇总，切回原问题仍显示原规则和原判断。本轮没有真实模型调用；模型输入预览、服务端问题隔离及建议接受路径由测试验证。论文/PDF/书籍专用导入仍未实现。


## 标签管理

规则编辑器中点击“新增标签”，填写名称、定义、纳入/排除条件；每题保留 1–8 个标签。“从下一版本移除”可在草稿中撤销，预览与确认发布后才生效。草稿最多容纳 24 个标签项（含待移除项），防止反复操作无限累积。

改名保留标签身份；发布移除后，不复用原标签 ID，重新新增视为新标签。历史标注保留原标签名称与引文，标注页会提示存在已移除标签；当前问题的旧判断进入复核，其他问题不受影响。新增/移除预览同时展示完整定义与纳入/排除条件。标签合并、自动重映射、撤销已发布版本仍未实现。


## 材料类型与来源

导入时支持访谈、论文、书籍、其他类型，可填写作者／署名、年份／日期、HTTP(S) 来源链接及章节／页码。原文面板、证据汇总、JSON 导出恢复及模型请求快照保留这些信息。旧材料显示“来源未记录”，不猜测补填。

章节／页码是本次导入整份摘录的范围，不是逐段精确页码；不同范围需分次导入。来源由研究者填写，系统不验证真伪、抓取链接或解析 PDF/OCR。链接当前以文本展示。导入后可通过“更正来源信息”追加修订；逐段定位仍待实现。新增字段有长度限制，不改变原有 20 万字符材料上限。


## 来源更正与历史

原文旁点击“更正来源信息”，修改来源并填写原因后保存。“来源修改记录”保留导入时的信息、每次更正、时间与原因。可为旧材料补录缺失来源。原文和原始来源不会被覆盖，历史随 JSON 导出恢复保留。

更正对材料的所有研究问题生效；汇总显示当前来源。已确认人工判断不自动失效，涉及作者归属变化时需主动复核。基于旧来源的未审核 AI 建议不能接受，来源在生成过程中变化时放弃结果，不自动重试。更正原因最多 1000 字，每项目最多 1000 条记录。撤回更正可再次填写原值并说明原因，不能删除已有记录。
