# TraceNote 设计演进与决策记录

这份记录用于产品复盘和面试准备。区分用户提出的问题、实现决策、实际证据与尚未实现的设想。除明确标注日期外，早期讨论按阶段重建，不伪造逐字对话。项目由用户提出方向、AI 编程助手协助实现与验证；不能将开发验收描述为独立用户研究。

## 起点：让访谈判断能够回到原文（早期阶段）

问题：AI 可以给访谈贴标签，但研究者需要知道依据是哪句话、谁确认了结果、修改规则后哪些判断失效。

决策：将模型建议和人工确认分开；保存精确引文与段落编号；规则版本不可覆盖；发布新版本后保守地将全部旧判断置为待复核。主题汇总只使用当前版本已确认记录。

取舍：不自动确认，牺牲部分操作速度换取可审查流程。SQLite 保存完整快照，便于实现和追溯，但存储随历史增长，不适合大型语料。这里只证明流程可用，未证明节省了研究者时间。

## 2026-11-11：评估没有显示标签准确率优势

16 个合成案例、两种提示、32 次响应；两组都匹配助手编写的参考标签。随后 8 个多段目标、16 次响应，标签集合仍都匹配；一条直接提示输出因同标签重复引文被应用拒绝。

判断：不能把数据契约拒绝称为分类错误，也不能声称工作台比直接提示更准确。保留无差异结果和原始输出。工程价值首先是审核与追溯，效果仍需独立研究者验证。

证据：`eval/results/synthetic-v1/`、`eval/results/context-v2/`。

## 2026-11-16：从短片段走向长距离上下文

用户要求聚焦产品而非简历，同时明确任何运行都要避免突然耗尽内存。

决策：使用四篇约 2,650 字的人造距离压力材料，串行运行；限定文件大小、上下文字符数、请求数、输出预算，并检查峰值进程 RSS。重复中性背景用于控制距离，不能冒称自然完整访谈。256 MiB 检查是检查点停止机制，不是操作系统硬内存上限。

发现：相邻上下文遗漏时间限定；即使补充远处文本，也有把同事经历当成本人经历的情况。所有输出都通过字面引用校验，说明“引文存在”不等于“解释正确”。首轮八次请求峰值 33.97 MiB。

证据：`eval/results/long-context-v1/`。

## 2026-11-16：明确研究对象与时间范围

判断：除了上下文缺失，研究任务本身也没有充分说明“研究谁、哪个时间段”。

决策：将研究对象和时间范围加入规则版本，预览后发布；范围变化使旧判断失效；模型建议保留请求时范围，不能套用后来的版本。旧版本不被静默补写范围。

结果：八次串行回归峰值 34.30 MiB。完整上下文的四个案例全部匹配参考，其中人物归属案例改善；两个相邻上下文时间歧义案例仍未触发复核。输入范围和提示同时改变，且只采样一次，不能归因于单个改动或推断一般性能。

证据：`eval/results/long-context-scope-v2/`、`docs/architecture.md`。手动补充上下文仍未实现。

## 2026-11-19：用户提出多材料、多问题与引述反驳

用户提出两项扩展：材料不止访谈，还包括论文、学术书籍；同一平台或项目可以研究多个问题。用户同时给出关键反例：文章先引述“生活水平提升导致退出公共交通”，随后写“但实际上并非如此”。关键词出现不能当成作者支持该原因。

分析：问题至少有三个维度：上下文是否充分；观点属于谁；本文作者/当前受访者是否认可该解释。即使完整输入，只有“主题标签＋引文”的数据结构也无法清楚表达支持、反对或仅提及。

决策顺序：先增加观点归属与态度，再引入独立研究问题，最后扩展论文/书籍的导入及章节页码等来源信息。沿用可复核的原文证据路径，而非仅做关键词检索。

本轮实现范围：

- 每条标注可记录观点归属 holder、作者/受访者态度 stance，以及当前段落内的态度依据 stanceQuote。
- 态度分为支持、反对、仅提及、待核；旧记录显示未判定，不默认支持。
- 模型提出态度建议，人工修改或确认；汇总按态度分组，默认仅显示支持。确认反对材料不会使其进入支持集合。
- 态度依据与主题引文分开，可以选取包含转折/否定的更长片段；当前只支持同一段落内的连续依据。跨段态度依据暂不支持，需保留待核。
- 原文匹配检查只是结构保障；不能机械证明作者立场，也不能证明作者反驳已成立。

尚未实现：多研究问题及各自规则版本；PDF/学术书籍专用导入、页码定位、OCR；跨段多证据关联；用户选择附加上下文；命题之间的关系图；独立研究者评估。当前任务与四个初始标签仍围绕公共交通退出原因，不能宣传为已经通用的学术研究平台。

## 面试叙事提纲（不是效果承诺）

“最初做的是访谈标注和证据回溯。早期合成评估没有显示模型准确率提升，因此保留负结果，转向检查研究流程的可靠性。长距离案例暴露了时间和人物归属问题，于是把研究范围纳入版本管理。用户随后提出文章引述后反驳的例子，促使我们从主题标签扩展到观点归属和态度；汇总必须区分支持、反对与提及。每一步都有失败案例或明确需求驱动，也记录哪些风险仍未解决。”

面试应能说明：为什么不把旧标注默认视为支持、为什么引文合法仍可能语义错误、为什么不一次塞入全文、为什么修改研究范围需要新版本。不得声称上线规模、真实用户采用、研究效率提升或已验证泛化准确率。

## 本轮验证结果（2026-11-19）

29 项 Python 测试和 9 项 JavaScript 测试通过。四个围绕生活水平解释的合成案例分别覆盖支持、反对、引用和无法判断；四次真实模型调用均输出预设态度，并通过引文校验。串行评估进程峰值 33.78 MiB。参考由开发助手编写、单次采样、不是保留集，不能声称解决全部否定/反问/跨段归属问题。

在隔离数据库的浏览器验收中，手动保存“票价解释被反驳”的记录，确认支持分组为零，反对分组显示一条并保留否定句。测试没有改写实际项目数据库。模型侧案例使用测试专用标签“生活水平提升”，不表示界面已经具备新增标签或通用多问题研究能力。

证据：`eval/results/stance-v1/`、`tests/test_stance.py`、`tests/domain.test.js`。后续讨论应继续追加到本文件，保留旧决策及改变原因，不用新结论覆盖历史。


## 2026-11-19：跨段反驳与有界上下文

用户继续授权推进，并要求保留设计路径、避免内存骤增。同段态度字段仍无法表达“第一段引用、第四段反驳”；因此将主题引文与态度依据的来源段落分开。

本轮已实现：同一材料最多手选 4 个补充段落，与相邻上下文合并去重并按原文顺序发送；先预览再请求；单次序列化任务内容上限 40,000 字符。态度依据增加 stanceParagraphId，模型只能引用实际看到的段落，人工引用只能来自同一材料。汇总显示两个来源，支持跳回态度依据；保存请求快照供追溯。

取舍：暂用段落 ID 输入，后续可改选择器。没有自动全文检索，也不强行把全文送入模型。快照提高可追溯性，但会增大 SQLite 历史体积。字数限制不是全进程内存保证。结构校验能阻止跨材料和未发送段落引用，不能证明语义判断正确。旧记录默认沿用当前段落，不改写历史判断。

验证：34 项 Python、10 项 JavaScript 测试；隔离浏览器完成预览取消、测试建议生成、载入审核、确认、支持组排除、反对组展示和跳到 P004。测试使用 TEST-ONLY 模型和合成材料，没有改写实际数据库。本轮没有真实模型调用，不能将界面验收写成跨段理解准确率提升。测试服务器用后停止。证据：tests/test_context_links.py、artifacts/cross-context-verified.png。

下一步：小规模串行真实模型对照，比较有无远端反驳段的输出，记录失败；再推进独立研究问题及规则隔离。论文/书籍专用导入、多问题仍未实现。以上新增代码当前仅本地保存，尚未同步私有 GitHub。


## 2026-11-19：真实模型的跨段对照与保留的局限

用户授权继续后，先验证跨段信息是否改变判断。设计两篇简短合成材料：开头均为“甲研究认为，退出公共交通是因为生活水平提升”，邻段说明本文评价见后文；P004 一篇明确反驳，一篇明确认可。两种输入分别提供邻段、邻段加 P004。参考在调用前固定，缺少后文允许仅引述或待核，不要求模型猜隐藏结论。

结果：4 次真实模型请求串行完成，无重试；四份输出均通过结构及原文校验，并匹配对应视图的态度与来源参考。邻段均为 mentions，补段分别为 opposes/supports，态度依据都来自 P004。人工检查四次 holder 均为“甲研究”，与原始主张归属一致；作者态度由独立 stance 字段表达。评估进程峰值 33.94 MiB；检查阈值 256 MiB，每次输入限 8,000 字符。内存检查发生在调用前后，不是系统级硬上限。

保留的问题：两个完全相同的邻段输入，只有一次明确输出缺少后文的复核/弃权说明；另一次仅标 mentions。宽松参考均接受，因此不能将 4/4 描述为完整可靠性或准确率，也不能保证模型总会主动提醒遗漏上下文。后续可考虑在产品中明确展示“仅提及”与“作者态度尚不可知”的区别，但本轮不因两个输出就修改提示或参考。

证据：eval/cross_context.py、eval/results/cross-context-v1/。新增两项评分器测试，Python 共 36 项通过；此前 10 项 JS 测试本轮代码未改动。未接触实际研究数据，无服务器常驻。本次仍是开发助手编写案例、单次采样，没有真实论文或独立研究者评价。

面试叙事可讲：用相同开头、相反结尾控制上下文变量；分别检查结构合法、态度正确、来源可追溯；同时保留成功结果与不一致的缺失信息提醒。下一阶段推进多研究问题的数据隔离，另行设计更复杂自然材料评估。代码与结果仍仅本地，尚未同步 GitHub。


## 2026-11-19：从单一问题到共享材料的多问题研究

用户授权继续推进先前提出的“一次研究多个问题”。设计采用材料共享、判断按问题隔离：复制整套访谈容易使来源分叉；仅在界面换问题名称又会把旧判断混进新问题，因此把 questionId 放在不可变规则版本上，人工标注/模型建议通过 versionId 继承归属。

旧版本缺少 questionId 时视为 Q1（原公共交通问题），不重写历史。版本编号保持项目内全局递增；每个问题取自己的最新版本。规则发布仅使当前问题的判断失效。AI 输入携带实际问题文字，并仅检索该问题的纠正与历史建议；移除了模型提示中固定“当前放弃公共交通”的任务声明。

界面允许创建并切换最多 20 个问题，每题最多 500 字，创建时提供一个初始标签。问题文字暂不允许直接修改，含义改变应新建，避免静默改变旧证据解释。当前选择是浏览器本地状态，内容保存可能携带它；首次打开默认 Q1。共享的是材料与稳定段落 ID，不是标注结论。

验证：42 项 Python、11 项 JavaScript 测试通过，覆盖旧数据、问题归属不可覆盖、跨问题规则失效隔离、模型输入与纠正筛选、错误版本接受拒绝、原问题 AI 建议在新问题创建后仍可接受，以及备份恢复。隔离浏览器中，先在原问题确认 P001，再创建“照护责任如何影响出行？”；新问题 P001 仍待标注，随后将“我得接孩子”确认进入其汇总；切回原问题不出现照护标签。模型预览显示新问题和独立规则。证据：tests/test_questions.py、tests/domain.test.js、artifacts/questions-verified.png。

资源与边界：串行验证，无真实模型调用，仅一个临时服务器且验收后停止；未修改实际数据库。新增问题仅一个初始标签，已有问题内增删标签界面、跨问题综合分析、问题改名、PDF/书籍专用导入仍待做。以单元测试及测试模型确认隔离，不表示已验证多学科语义质量。当前代码和源码包仍仅本地，尚未同步 GitHub。

面试叙事新增：为什么让版本拥有研究问题、如何兼容无归属的旧记录、为什么问题 B 的规则修改不能使问题 A 的研究判断失效。下一步先完善每题标签管理，保留稳定标签 ID 与版本历史，再处理学术材料来源。


## 2026-11-19：每题标签增删与稳定身份

用户授权继续推进多问题后的标签管理。原先只能编辑固定标签，新问题只有一个初始标签，不足以支持实际研究者演化编码体系。

实现：规则编辑器允许新增、改名、移除；草稿移除可撤销，修改后必须重新预览，再明确发布。每题保留 1–8 个标签，单次草稿最多 24 个条目（含待移除项），文本字段有输入长度限制。新增/移除的差异预览包含定义、纳入与排除条件，不只显示名称。

关键取舍：标签身份与名称分开，改名保持 ID；发布移除后不允许复用该问题的旧 ID。若后来重建同名标签，按新概念处理，不自动继承旧判断。后端对完整版本历史检查身份复用，因此自制备份中含“移除后复用同 ID”的历史会被拒绝；现有项目历史无此用法。标签合并和旧证据映射需要独立设计，不能当作普通改名。

移除没有删除旧引文。历史面板按原版本显示当时标签名称；当前表单提示存在已移除标签，要求研究者按现行规则重新判断。发布只使当前问题的判断失效，旧证据不进入新规则汇总，其他问题保持原状。

验证：44 项 Python、12 项 JavaScript 测试通过，包含空标签集、超上限、去空白重名、旧身份复用拒绝、改名保持 ID、旧证据保留及新增完整定义差异。隔离数据库浏览器实际完成移除可靠性标签、新增照护标签、撤销移除、再移除、预览、发布及刷新；旧“公交晚到二十分钟”引文保留，P001 显示版本待复核和已移除标签提醒。证据：tests/test_questions.py、tests/domain.test.js、artifacts/labels-verified.png。

本轮串行测试、无真实模型调用、临时服务已停止，未修改实际研究数据库。修改与源码包仍仅本地，尚未同步 GitHub。下一步推进访谈/论文/书籍的材料类型及来源元数据，先做好可追溯来源，再讨论 PDF 与 OCR。

## 2026-11-20：可更正的来源与不可覆盖的历史

用户继续授权推进来源更正。前一版将来源保存在不可变 Document 上，能避免静默覆盖，但录错页码后无法在界面修正。现在保留原始来源，另加 sourceRevisions 追加记录，显示最新来源与完整更正历史；每次必须写原因，最多 1000 字，每项目最多 1000 条。

设计取舍：更正出处不等于改写原文，不直接覆盖已确认的人工研究判断。材料在多个问题间共享，因此最新出处对各问题汇总一致生效；作者归属变化可能影响原判断，界面提醒人工复核，但尚未自动创建复核队列。后续可按字段变化区分纯页码纠错与归属变化，避免所有修订都强制重做。

AI 一致性：请求快照增加来源修订号，生成过程中更正来源会放弃结果；基于旧来源的建议不能再接受，可拒绝或重新生成。即使把字段改回原值，修订号变化仍使原建议失效。更正表单保留打开时项目修订号，其他页面更新后旧提交被拒绝，不覆盖新状态。

验证：50 项 Python、14 项 JavaScript 测试通过，包括历史追加/恢复、禁止普通保存伪造更正、空原因与无变化拒绝、并发冲突、旧建议禁止接受、生成中来源变化放弃结果及前端最新来源解析。隔离浏览器将合成材料页码由 42–44 更正为 45–47，历史保留原值、时间与说明。证据：tests/test_sources.py、tests/domain.test.js、artifacts/source-history-verified.png。

资源与交付：串行测试，无真实模型请求，临时服务器已停止，实际研究数据库未改动。代码、设计记录和源码包均为本地更新，未同步 GitHub。下一步优先完善来源更正后的复核提示与证据导出，再推进 PDF 页码解析，避免扩展输入格式时丢失这条溯源链。


## 2026-11-23：来源更正后的人工复核与证据导出

承接 11 月 20 日的来源历史：只更新引用展示，会使旧判断看起来像已经核对过新出处。现在每次人工保存绑定来源版本；任一来源更正都会使该材料在所有研究问题下的旧判断进入“来源待复核”。不改写历史，重新确认后才能重新计入汇总。规则和来源同时变化时优先提示来源待复核，并要求核对当前规则。无来源版本的旧记录按初始版本 0 处理，不根据时间猜测。

选择保守失效：页码小改也会触发复核，增加人工工作，但避免自动判断哪些来源改动不影响归属。后端同时校验新人工保存的来源版本，AI 建议确认由服务端绑定当前版本，防止仅在界面过滤。

证据 JSON 报告仅包含当前问题、规则和所选立场的已确认证据，附原文、UTF-16 偏移、跨段态度依据、来源版本及人工记录。共享原文不意味着跨问题混合导出；引用关系不意味着作者支持观点。报告保留 fictional 标识，来源由用户录入，未核验真实性。完整恢复仍使用项目 JSON 备份。

内存约束：单次导出上限 5,000 条和约 100 万序列化字符，逐条检查；串行运行测试、单个临时服务、无真实模型调用。52 项 Python 和 16 项 JS 测试通过；浏览器验证来源待复核、汇总排除及实际 JSON 下载。使用独立临时 SQLite，未修改用户研究数据。设计限制：目前无 PDF/OCR，报告不是项目备份，也不是事实真实性或研究准确率证明。

## 2026-11-24：首次真实论文的两次模型上下文对照

用户授权继续两次真实调用。冻结论文摘录、两组实际输入、标签、研究范围、参考解释、适配器和运行器哈希，再发出请求。仅两组 context 不同；两组都明确提供引述出处和评价主体，不能把结果描述为模型自行发现未标明的作者身份。请求开始前写入 started 记录，防止中断后自动重复付费；失败保存并停止。

## 2026-11-24：准备对参考答案盲评的三任务试填包

用户授权继续准备；中途明确询问是否停止，已停止并说明当时仅阅读文件。用户重新说“继续”后恢复制作。采用现有两份真实来源，三个任务分别关注达尔文让步后的态度、条件论证、论文中引述观点与本文评价。三个任务共享两份来源，不能当作三个独立文档；本轮没有新增材料或模型调用。

设计取舍：只提供完整材料视图，不把仅引述/补充评价两个阶段同时交给同一评审者作为独立任务，减少阶段间记忆污染。包内保留出处与被引作者定位，但隐藏开发解释与模型输出，准确称为“对参考答案盲评”，不是双盲。每份回答分开记录 claimHolder 和 evaluator，避免立场看似一致却判断了不同主体。

交付采用 ZIP 三文件白名单，组织者参考保留在独立目录；不得向评审者发送含参考与模型结果的完整源码包。空白模板不预填 stance、证据或解释。校验器检查版本、完成状态、证据唯一定位及来源；比较器保留全部原始解释，只列描述性立场一致/分歧，不自动裁决、不把一致当准确。真实响应只读，不自动存入公开材料目录。

验证：新增 3 项测试覆盖打包白名单/空白答案、版本及错材料证据拒绝、保留分歧且拒绝相同评审代号。构建峰值 RSS 29.39 MiB，零模型调用。当前真实评审者及提交均为 0；测试中的 TEST-A/TEST-B 是明确标记的验证器测试数据，不计入研究结果。后续独立评审需要两位真人，助手不可代替。设计记录和源码包本地保存，未邀请或联系他人。
