# 用真实书籍摘录理解 TraceNote

材料：[Charles Darwin, On the Origin of Species, 1860 年第二版，第 VI 章](https://darwin-online.org.uk/Variorum/1860/1860-186-c-1859.html)。摘录从印刷页 186 开始，后续句子跨页；不声称整个摘录只在 186 页。原著已进入公版，本案例只保留两句连续原文，未复制校勘编辑内容或后版新增句子。见 `eval/real-source.json` 的原文、来源、规范化说明与 SHA-256。

这是真实书籍材料，不是真实访谈；判断和研究问题由开发助手编写，不是独立研究者的金标准。

## 为什么这个例子有用

开头承认复杂眼睛通过自然选择形成似乎难以想象，随后用 “Yet reason tells me” 转折，提出有用渐变、可遗传变异等条件来回应这一困难。这里只读开头会误判作者的整体立场。它是作者自己的让步与回应，不是引用别人，也不能仅凭这段条件论证就声称所有条件已获得实证证明。

TraceNote 的作用是把研究者的判断拆成可追踪的记录：研究问题是什么、标了哪个观点、证据在哪里、谁在表达、其立场是什么、依据是哪一句、采用哪个规则和来源版本。

## 同一材料研究两个问题

| 研究问题 | 本次演示判断 | 核对方式 |
|---|---|---|
| 作者是否将眼睛复杂性视为否定自然选择的理由？ | 对该反对意见记为 opposes | 不能只看开头的困难陈述，要保留转折后的完整条件回应 |
| 作者是否以有用渐变作为回应困难的条件？ | 对“提出这一论证条件”记为 supports | 支持的是这个论证步骤，不等于证明演化过程的全部事实 |

两条问题共享同一份原文，各有自己的标签、判断和汇总。第一题的反对证据不进入支持分组，第二题的支持证据也不会混入第一题。

## 来源修正与复核

演示先只记录章节，再补上核对后的版次和起始页信息。旧来源不覆盖，旧判断保留，但两个问题都显示来源待复核。仅重新确认第一题后，它恢复计入汇总，第二题仍待复核。

导出的 `evidence.json` 包含第一题的研究问题、完整规则、原文、观点归属、反对立场、态度依据、出处和人工复核引用。`reconfirmed.json` 是可恢复的完整演示项目，其中默认教学材料明确标为虚构，达尔文摘录标为真实。不要把恢复备份操作应用到正在使用的项目来试验；验收脚本自动使用临时数据库。

## 复现

```sh
python3 eval/real_workflow.py --node /path/to/node
```

若 node 已在 PATH，可省略 `--node`。脚本完全离线，不读取 `.env`，不调用模型，不访问用户数据库。运行会重新生成 `eval/results/real-workflow-v1/` 下的开发验收产物；随机问题 ID 与时间戳可变，原文哈希保持固定。它不是冻结的付费模型评估缓存。

验收覆盖：导入原文与来源、两个问题的标注隔离、立场分组、后端保存、来源历史追加、跨问题失效、单题重新确认、导出及备份恢复。验证通过代表流程约束成立，不代表作者立场可被模型自动正确识别。

资源限制：1 份摘录、2 个新增问题、128 KB 单输入、100 万字符单输出、两个串行 Node 子进程，各最多 20 秒。每个进程检查 256 MiB RSS 预算，无失败重试；不是操作系统级内存硬上限。首次记录 Node 峰值约 43.11 MiB，Python 约 29.44 MiB。

## 本次暴露的后续工作

当前立场中文名称仍偏交通研究（例如“支持该原因”），而底层 supports/opposes 适用于更一般的观点。应将界面和请求提示统一成通用研究措辞，再加入真实论文的“引用他人后反驳”案例；不能把本例让步结构直接当作引述归属测试。随后才做少量、预先固定参考解释的真实模型验收，并单独报告误读和不确定性。
